# Выгрузка метрик эксперимента

Задача E-01. Определения метрик — `MVP_SCOPE.md`, шаг 5; почему данные лежат в трёх базах и
сводятся вручную — ADR-0010.

## Как получить

Локальная среда:

```bash
npm run metrics
npm run metrics -- --csv ./experiment-data
```

Скрипт `tools/metrics.mjs` выполняет запросы ниже, соединяет результаты по идентификаторам
пользователей и печатает M1–M4. С ключом `--csv` он дополнительно сохраняет `pairs.csv`: по строке
на пару «зритель — кандидат» с последним просмотром и состоянием запроса.

**В выгрузку попадают только обезличенные идентификаторы, счётчики и время.** Имён, анкет и
контактов в ней нет. Сам файл всё равно содержит связи между людьми: храните его как
персональные данные и не публикуйте.

В любой другой среде те же запросы выполняет оператор под ролью с доступом только на чтение.

## Запросы

### Profile — `profile_db`

```sql
-- M4, числитель: заполнившие анкету
SELECT count(*) FROM profile;
```

### Keycloak — `keycloak_db`

```sql
-- M4, знаменатель: зарегистрированные пользователи (без сервисных учётных записей).
-- Запрос к внутренним таблицам Keycloak: при обновлении Keycloak проверить, что он работает.
SELECT count(*)
FROM user_entity u
         JOIN realm r ON r.id = u.realm_id
WHERE r.name = 'sozhiteli'
  AND u.service_account_client_link IS NULL;
```

### Matching — `matching_db`

```sql
-- Все просмотры карточек. Для каждой пары выбирается последний просмотр до запроса
-- (если запрос был) или последний вообще - это делает скрипт.
SELECT viewer_id, candidate_id, matched_count, compared_count, viewed_at
FROM candidate_view
ORDER BY viewed_at;
```

### Interaction — `interaction_db`

```sql
SELECT sender_id, recipient_id, status, created_at, responded_at
FROM contact_request;

-- Справочно: сколько участников указали контакт
SELECT count(*) FROM contact;
```

## Как считаются метрики

| Метрика | Расчёт |
|---|---|
| M1 | Пары из `candidate_view`, для которых есть `contact_request` с `sender_id = viewer_id` и `recipient_id = candidate_id`, делённые на все пары |
| M2 | `accepted / (accepted + declined)`; ожидающие ответа показываются отдельно |
| M3 | Средняя доля `matched_count / compared_count` у пар с запросом и у пар без запроса (пары с `compared_count = 0` не учитываются) |
| M4 | Анкеты / зарегистрированные пользователи |

Ограничения:

- Для пар с запросом в M3 берётся последний просмотр **до** отправки запроса: это сравнение
  человек видел перед решением. Если карточку перед запросом не открывали, берётся просмотр после
  и скрипт сообщает число таких запросов. Запрос без единого просмотра карточки в M1 не входит.
- M3 — сравнение средних, а не доказательство причинной связи. При малом числе пар вывод делать
  нельзя: смотрите на распределение в `pairs.csv`.
- Пороги успеха не заданы (`MVP_SCOPE.md`, Q-2): решение о подтверждении гипотезы принимает
  владелец продукта.
