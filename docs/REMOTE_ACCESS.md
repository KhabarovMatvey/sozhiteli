# Открыть «Сожители» с телефона через интернет, используя ПК как сервер

Подготовлено 16 октября 2026 года для Windows и текущего Docker Compose.

Этот вариант использует **Tailscale Serve**: приложение работает на ПК, а телефон подключается к его приватной сети через интернет. На телефоне нужны Tailscale и браузер; собирать мобильное приложение Expo не нужно. Доступ возможен и через мобильный интернет. ПК, Docker и Tailscale должны работать; спящий или выключенный ПК сайт не обслуживает.

Это не общедоступная ссылка: доступ имеют устройства вашей сети Tailscale с разрешённым политикой доступом. Для обычной публичной ссылки без Tailscale нужен другой вариант размещения. Не включайте Tailscale Funnel для этой локальной dev-среды.

## 1. Установить Tailscale

1. Установите Tailscale на Windows и телефон с [официальной страницы](https://tailscale.com/download).
2. Войдите на обоих устройствах в один аккаунт и включите подключение.
3. Найдите полное DNS-имя компьютера в панели Tailscale: например, `my-pc.example-tailnet.ts.net`. Используйте реальное имя, а не этот пример.
4. Если после установки команда `tailscale` не находится, откройте новый PowerShell. Обычный путь Windows — `C:\Program Files\Tailscale\tailscale.exe`.

Дополнительный проброс портов на домашнем роутере для этой схемы не требуется. На ПК уже установлен другой VPN; если Tailscale не подключается или не открывает имя компьютера, временно отключите другой VPN на время диагностики. На телефоне другой активный VPN также может мешать Tailscale.

## 2. Задать имя ПК и HTTPS-прокси

Откройте PowerShell в каталоге проекта. Замените пример домена своим полным DNS-именем ПК без `https://`, порта, пути и точки на конце:

```powershell
Set-Location -LiteralPath 'D:\Сожители'
$env:SOZHITELI_REMOTE_HOST = 'my-pc.example-tailnet.ts.net'

tailscale serve --bg --https=443 http://127.0.0.1:3000
tailscale serve --bg --https=8443 http://127.0.0.1:8080
tailscale serve --bg --https=10000 http://127.0.0.1:8081
tailscale serve status
```

Первый запуск может показать ссылку для включения HTTPS/Serve в аккаунте. Откройте её и завершите настройку, затем повторите команду, если потребуется. Правила доступа Tailscale должны разрешать телефону TCP-порты 443, 8443 и 10000 компьютера.

Команды добавляют три прокси на указанных HTTPS-портах. Если Tailscale Serve уже обслуживает другие приложения на этих портах, сначала проверьте `tailscale serve status` и не заменяйте их без необходимости.

| Внешний HTTPS-адрес | Локальный сервис |
|---|---|
| `https://ИМЯ-ПК.ts.net/` | Web на `127.0.0.1:3000` |
| `https://ИМЯ-ПК.ts.net:8443/` | Edge API на `127.0.0.1:8080` |
| `https://ИМЯ-ПК.ts.net:10000/` | Keycloak на `127.0.0.1:8081` |

В таблице `ИМЯ-ПК.ts.net` обозначает полное DNS-имя из шага 1. Сертификаты HTTPS получает Tailscale. Для входа через PKCE это важно: библиотека web использует `crypto.subtle`, недоступную обычной HTTP-странице по сетевому IP.

## 3. Разрешить новый адрес в Keycloak

Перед переключением Docker-конфигурации откройте на ПК [административную консоль Keycloak](http://localhost:8081/admin/). Учётные данные администратора находятся в локальном `deploy/compose/.env` (`KEYCLOAK_ADMIN_USERNAME` и `KEYCLOAK_ADMIN_PASSWORD`). Их не нужно никому отправлять.

Выберите realm `sozhiteli` → Clients → `sozhiteli-web` → Settings. Добавьте значения ниже, сохраняя имеющиеся локальные адреса. Везде замените пример домена своим:

- **Valid redirect URIs:** `https://my-pc.example-tailnet.ts.net/auth/callback`
- **Web origins:** `https://my-pc.example-tailnet.ts.net`
- **Valid post logout redirect URIs:** добавьте `https://my-pc.example-tailnet.ts.net/`

Сохраните изменения. Это настройки работающего realm: они хранятся в PostgreSQL. Изменение `realm-dev.json` само по себе на уже импортированный realm не действует. Не используйте `infra:reset` для применения настроек: эта команда удаляет данные.

## 4. Запустить проект с удалёнными адресами

В том же окне PowerShell с установленной переменной `SOZHITELI_REMOTE_HOST`:

```powershell
docker compose -f deploy/compose/compose.yaml -f deploy/compose/compose.remote.yaml --profile app config --quiet
docker compose -f deploy/compose/compose.yaml -f deploy/compose/compose.remote.yaml --profile app up -d --build --wait
```

Пересборка web обязательна: адреса API и провайдера входа включаются в браузерный код во время сборки. У контейнеров сохраняется тот же проект Compose и том PostgreSQL; данные не сбрасываются.

Дополнительный файл настраивает внешний hostname Keycloak, issuer для трёх сервисов, CORS и адреса web. Исходная локальная конфигурация не переписывается. Новые контейнеры инфраструктуры и опубликованные в интернете порты Docker не добавляются: доступ принимает Tailscale.

## 5. Открыть на телефоне

Включите Tailscale на телефоне и откройте в браузере:

```text
https://my-pc.example-tailnet.ts.net/
```

Используйте своё имя. Для проверки именно интернета можно выключить Wi-Fi на телефоне и оставить мобильные данные с Tailscale. Войдите в проект и проверьте анкету, кандидатов и запросы. При переходе на новый issuer может потребоваться повторный вход.

В удалённом режиме основной адрес для браузера ПК тоже HTTPS-адрес Tailscale. Старый `http://localhost:3000` не считается полноценным вторым адресом: web собран с удалённым API, а CORS разрешает новый origin.

## 6. Диагностика

| Симптом | Что проверить |
|---|---|
| Страница не открывается | ПК включён; Docker работает; Tailscale подключён на обоих устройствах; Serve показывает три маршрута; нет запрета в access policy |
| Главная работает, API нет | Доступность порта 8443; настройки CORS; выполнена пересборка web с нужным именем |
| Keycloak показывает `Invalid parameter: redirect_uri` | Адрес callback добавлен именно в клиент `sozhiteli-web` работающего realm |
| Бесконечный вход / `401` после входа | Совпадают внешние hostname и issuer; выполнен запуск с обоими Compose-файлами; выполнен новый вход |
| Переходы ведут на localhost | Не пересобран web либо не применён внешний hostname Keycloak |
| Перестало работать после нового PowerShell | Снова установите `$env:SOZHITELI_REMOTE_HOST` перед Compose-командами |
| Не видно других устройств Tailscale | Проверьте аккаунт, подключение, другой VPN, сеть и политику доступа |

Безопасная проверка контейнеров:

```powershell
docker compose -f deploy/compose/compose.yaml -f deploy/compose/compose.remote.yaml --profile app ps
```

Не публикуйте полный вывод `docker compose config`: он может содержать подставленные секреты. Для проверки синтаксиса используйте `config --quiet`.

## 7. Отключить доступ и вернуться к локальному режиму

Следующие команды отключают только три настроенных HTTPS-прокси. Они предполагают, что на этих портах вы настроили именно этот проект:

```powershell
tailscale serve --https=443 off
tailscale serve --https=8443 off
tailscale serve --https=10000 off

docker compose -f deploy/compose/compose.yaml --profile app up -d --build --wait
```

Локальная пересборка возвращает исходные адреса web и issuer. Локальные redirect URI в Keycloak должны оставаться сохранены. База и анкеты остаются на месте. После переключения снова войдите в приложение.

Не запускайте обычный `npm run app:up`, пока хотите сохранить удалённую конфигурацию: эта команда использует только исходный Compose-файл и вернёт локальные настройки.

## Проверка подготовленных файлов

Файл `compose.remote.yaml` проверен через `docker compose ... config --quiet` с демонстрационным DNS-именем. Подключение телефона, выпуск сертификатов, вход через Tailscale и запуск удалённого режима ещё не проверены: на этом ПК Tailscale во время подготовки не установлен. Текущая работающая среда не переключалась и не пересобиралась.

Официальные инструкции: [Tailscale Serve](https://tailscale.com/docs/features/tailscale-serve), [синтаксис CLI](https://tailscale.com/docs/reference/tailscale-cli/serve).
