# ADR-0013. Страницы входа: своя тема Keycloak и регистрация только по email

Статус: принято · 2026-10-16

## Контекст

Вход и регистрация целиком отданы Keycloak (ADR-0002). Страницы по умолчанию — на английском, в
оформлении Keycloak, а форма регистрации запрашивает имя и фамилию, которые системе не нужны:
имя для карточки человек указывает в анкете Profile (задача K-01, `SECURITY.md`, «Минимизация
данных»). Владелец продукта попросил, чтобы интерфейс выглядел цельно и был на русском.

## Альтернативы

| Вариант | Оценка |
|---|---|
| Оставить как есть | Английские страницы и лишние персональные данные при регистрации |
| Свой экран входа в приложениях с вводом пароля (password grant) | Пароль проходит через код приложений; противоречит PKCE-only для публичных клиентов (`SECURITY.md`) |
| Переопределить шаблоны FreeMarker (`login.ftl`, `register.ftl` …) | Полный контроль над разметкой; шаблоны меняются почти в каждом выпуске Keycloak, правки придётся переносить |
| Тема на React через внешний инструмент сборки тем | Новая зависимость и отдельный конвейер сборки ради двух страниц |
| **Дочерняя тема `keycloak.v2`: только CSS и русские тексты** | Шаблоны встроенные; меняются переменные и классы PatternFly 5 и несколько строк сообщений |

## Решение

1. Тема `sozhiteli` типа `login` (`deploy/compose/keycloak/themes/sozhiteli/login/`):
   `parent=keycloak.v2`, свой файл стилей `css/sozhiteli.css` поверх штатного, переопределения
   `messages/messages_ru.properties`. Тёмный режим выключен, как и в web. Шаблоны не
   переопределяются.
2. Realm: `loginTheme=sozhiteli`, интернационализация включена, единственный язык — русский.
3. Профиль пользователя realm: атрибуты `username` и `email`; `firstName` и `lastName` удалены,
   поэтому форма регистрации — почта и дважды пароль (`registrationEmailAsUsername` уже включён).
4. Политика паролей: `length(8) and notUsername and notEmail`. Защита от перебора — прежняя.
5. В Compose тема монтируется в `/opt/keycloak/themes/sozhiteli` только для чтения. В
   промышленной среде те же файлы кладутся в образ Keycloak или монтируются так же.

## Почему так

- Пароль по-прежнему видит только Keycloak; клиенты не меняются (PKCE, те же аудитории и роли).
- Обновление Keycloak не ломает вход: в худшем случае поменяются классы PatternFly и часть
  оформления вернётся к штатному виду — страницы останутся рабочими.
- Меньше персональных данных: Keycloak хранит только почту и хэш пароля.

## Недостатки

- Внешний вид ограничен тем, что позволяют стили: разметку страниц не изменить.
- Переопределённые тексты нужно сверять при обновлении Keycloak (ключи сообщений иногда
  переименовываются; тогда показывается штатный русский перевод).
- Политика паролей действует только для новых паролей; существующие учётные записи не
  проверяются.
- Импорт realm при старте (`--import-realm`) пропускает уже существующий realm. Изменения
  `realm-dev.json` попадают в работающую среду только после `npm run infra:reset` или вручную
  через `kcadm.sh` (так они и были применены 2026-10-16, `VERIFICATION.md`).

## Условия пересмотра

Понадобятся другие поля при регистрации, вход через внешних провайдеров с иной разметкой или
изменение страниц сверх возможностей CSS — тогда переопределение отдельных шаблонов с явным
списком файлов и проверкой при каждом обновлении Keycloak.
